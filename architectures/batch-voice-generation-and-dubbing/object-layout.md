# Object layout: batch voice generation and dubbing

One bucket per zone, with purpose prefixes inside each bucket. Lifecycle rules, Object Lock, replication, default encryption and Event Notification rules are configured per bucket, and an application key admits a single prefix, so separate buckets keep each policy and each key simple. There is no per-tenant prefix: the layout assumes a single organization.

Bucket names follow [`infrastructure/b2-provisioning/`](../../infrastructure/b2-provisioning/README.md): `<bucket-prefix>-voice-generation-<zone>`. The environment variables are the ones the [examples](../../examples/README.md#code-examples) read.

| Zone | Bucket | Variable | Object Lock | Lifecycle template |
|---|---|---|---|---|
| Incoming | `<bucket-prefix>-voice-generation-incoming` | `B2_INCOMING_BUCKET` | No | [`lifecycle-incoming.json`](../../examples/lifecycle-incoming.json) |
| Work | `<bucket-prefix>-voice-generation-work` | `B2_WORK_BUCKET` | No | [`lifecycle-work.json`](../../examples/lifecycle-work.json) |
| Releases | `<bucket-prefix>-voice-generation-releases` | `B2_RELEASES_BUCKET` | Optional, governance mode, set at creation | [`lifecycle-releases.json`](../../examples/lifecycle-releases.json) |
| Protected | `<bucket-prefix>-voice-generation-protected` | `B2_PROTECTED_BUCKET` | Yes, governance default retention | [`lifecycle-protected.json`](../../examples/lifecycle-protected.json) |

All four buckets are private and use SSE-B2 as the default encryption.

## Incoming bucket

```text
source/
  <source_id>.wav             # audio or video to dub or transcribe, or a text script for speech synthesis
  <source_id>.json            # sidecar: consent ids, language, requested job kind
```

- **Writes:** the application, through presigned PUT URLs or a key limited to `source/` with `writeFiles` only.
- **Reads:** the job runner; hosted providers through one presigned GET URL per job; self-hosted workers with a read key.
- **Events:** an Event Notification rule on `source/` for `b2:ObjectCreated:*` ([template](../../examples/event-notifications.json)).
- **Lifecycle:** objects under `source/` are hidden after the example period and deleted the next day; unfinished large uploads are cancelled. The template also carries rules for `contributions/` and `sessions/`, which this architecture does not use; they match nothing in this bucket. Set the period longer than the longest expected job and review, or a resubmission after a download failure will find no source.
- **Versions:** the job manifest records the source's `version_id`, so a re-upload under the same name does not change what an existing job refers to.

## Work bucket

```text
candidates/
  <job_id>/
    <language>/mix.wav            # dubbed or generated mix
    <language>/<speaker_id>.wav   # per-speaker stem, where available
    <language>/subtitles.vtt      # subtitles, where the provider returns them
    transcript.json               # provider output for transcription and call analytics, unchanged
    job-manifest.json             # written last; a review decision is a new version of this object
scratch/
  <job_id>/...                    # temporary files of self-hosted workers
```

- **Writes:** the job runner (`candidates/`), self-hosted workers (`candidates/`, `scratch/`). Each writer has its own key.
- **Reads:** the review tool through presigned GET URLs; the job runner for promotion.
- **Lifecycle:** `candidates/` and `scratch/` are hidden after the example periods and then deleted; unfinished large uploads are cancelled ([`lifecycle-work.json`](../../examples/lifecycle-work.json)). Each output's `expires_at` in the job manifest is computed from the `candidates/` period. The template's `evaluations/` rule matches nothing in this bucket.
- **CORS:** allow `GET` and `HEAD` from the review tool's origin only, when the review tool plays audio from presigned URLs in the browser.
- **Names:** `job_id` is generated by the runner and `speaker_id` is the pseudonymous id from the consent record; object names never contain a speaker's name.

## Releases bucket

```text
deliveries/
  <release>/
    <version>/
      <language>/mix.wav
      <language>/<speaker_id>.wav
      <language>/subtitles.vtt
      transcript.json
      job-manifest.json           # with promotion and lineage; written last
```

- **Writes:** the job runner, with a key limited to `deliveries/`. A `<version>` folder is written once; any change is a new version.
- **Reads:** recipients through presigned GET URLs, a CDN worker with a read-only key on `deliveries/`, and downstream jobs with read-only, expiring keys.
- **Lifecycle:** current versions are never hidden by lifecycle; hidden versions are deleted after a grace period, which lets a withdrawn delivery be hidden and then removed. Unfinished large uploads are cancelled.
- **Replication:** optional, to a bucket in another region ([template](../../examples/replication.json)). Deletes and hide markers are not replicated, so a withdrawal must be applied to the replica as well.
- **Object Lock:** optional. Governance mode keeps the ability to remove a delivery after a consent withdrawal.

## Protected bucket

```text
consents/
  <consent_id>.json           # consent and license record; a withdrawal is a new version
```

- **Writes:** the consent service, with `writeFiles` on `consents/`.
- **Reads:** the job runner before each submission, and auditors (with `readFileRetentions` and `readFileLegalHolds`).
- **Object Lock:** enabled at bucket creation, with governance-mode default retention ([template](../../examples/object-lock.json)).
- **Lifecycle:** only cancels unfinished large uploads; retention is governed by Object Lock.

## Keys

`provision.py` creates one key per purpose prefix (for example `voice-generation-work-candidates`) with `listFiles`, `readFiles` and `writeFiles`. Narrow them per component:

| Component | Bucket and prefix | Capabilities |
|---|---|---|
| Source uploader or URL signer | incoming, `source/` | `writeFiles` |
| Job runner | incoming, `source/` | `listFiles`, `readFiles` (also signs the provider's presigned GET URLs) |
| Job runner | protected, `consents/` | `listFiles`, `readFiles` |
| Job runner | work, `candidates/` | `listFiles`, `readFiles`, `writeFiles` (also signs review URLs) |
| Job runner | releases, `deliveries/` | `listFiles`, `readFiles`, `writeFiles` (also signs delivery URLs) |
| Self-hosted worker | incoming, `source/` | `listFiles`, `readFiles` |
| Self-hosted worker | work, `candidates/` and `scratch/` (two keys) | `listFiles`, `writeFiles` |
| CDN worker | releases, `deliveries/` | `readFiles` |
| Downstream job | releases, `deliveries/` | `listFiles`, `readFiles`, with an expiry |
| Consent service | protected, `consents/` | `listFiles`, `readFiles`, `writeFiles` |

A presigned URL carries the capabilities of the key that signed it, limited to one operation on one object; hosted providers never receive a key.

## Clean up

`python infrastructure/b2-provisioning/provision.py --bucket-prefix <your-prefix> --architecture batch-voice-generation-and-dubbing --cleanup` prints the commands that remove these keys and buckets. Read the notes in the [provisioning README](../../infrastructure/b2-provisioning/README.md#clean-up) first: deletion is irreversible, and versions under compliance retention or a legal hold cannot be deleted.
